# three-js-sandbox — 浸水シミュレータ（駆逐艦 島風）

旧日本海軍の駆逐艦 **島風**（1943 年竣工、全長 129.5 m）を実寸で作り、被雷・破口から浸水し、区画ごとに水が広がって沈んでいく様子を 3D で観察するシミュレータ。
艦内の水は **GPU 上の粒子法（MLS-MPM）** で解いており、扉・ハッチ・昇降口を通って実際に流れる。

## 動かし方

- Node.js 20 以上
- **WebGPU 対応ブラウザ**（Chrome / Edge 113 以降）。独立 GPU 推奨（RTX 3080 で「標準」画質 60 fps を想定）

```bash
npm install
npm start   # http://localhost:5173
npm test    # CPU 側（艦型・区画格子・水位と流量・波・艦体運動）のテスト
```

画質は画面左の「表示 → 画質」で切り替える（軽量: 格子 0.6 m・23 万粒子 / 標準: 0.5 m・39 万 / 高精細: 0.42 m・52 万）。

- **表示**: 外観 / **透視**（カメラの側の外板・甲板・壁だけを透かし、艦内を立体のまま見る。回り込むと透かす面が変わる）/ 断面（中心線で縦に切った側面図）。透視・断面では「甲板を外す」で上部構造を隠し、上甲板・下甲板を外して上から部屋に入れる
- **カメラ**: ドラッグで回転・右ドラッグで平行移動・ホイールでズーム、**W A S D** で前後左右・**Q E** で下降と上昇・**Shift** で速く
- **被害**: 艦体をクリックすると魚雷。シナリオには 1 本（1 区画）・隔壁をまたぐ 1 本（2 区画）から、4 本を順に撃ち込んで撃沈するものまである
- **空気圧**: 環境タブで破断の有効・無効と構造の強さを変えられる。水密扉タブで天窓やハッチを閉じると、閉じ込められた空気の振る舞いと破断を見られる

GPU が失われた場合は自動で止まり、次回は「軽量」で起動する。

## 島風の再現と推定

| 項目 | 値 | 出典 |
| --- | --- | --- |
| 寸法 | 全長 129.5 m・水線長 126.0 m・幅 11.2 m・深さ 7.02 m・喫水 4.14 m | Wikipedia（日・英）、navypedia |
| 排水量 | 公試 3,048 t（船型は喫水 4.14 m で 3,015 t、1% 差） | 同上 |
| 機関 | ロ号艦本式缶 3 基（1 基ずつ別の缶室、1・2 号缶の煙路は前部煙突へ）・タービン 2 基 2 軸 | 同上（缶室の配置は陽炎型: navypedia） |
| 兵装 | 12.7 cm 連装砲 3 基（2 番は背負い式）・61 cm 五連装魚雷発射管 3 基 | 同上 |
| 区画 | 水密隔壁 14 枚・15 区画。下甲板で弾薬庫・倉庫と居住区に分ける | **推定**（艦内配置の公開資料が無いため） |
| 復原性 | GM 0.95 m（重心の高さは船型の KM から逆算） | **推定** |

実艦と違う点（強化）: 実艦（陽炎型の系譜）の共通の機械室を中央の水密隔壁で前部・後部に分けた。区画をまたぐ水密扉・水密ハッチは既定ですべて閉じている（戦闘配置）。

## 物理モデル

| 対象 | 方法 |
| --- | --- |
| 艦体の運動 | Rapier の剛体。艦体を 0.8 m のセルに分け、波の中の浮力・線形減衰・形状抵抗を合力とトルクにして加える |
| 波 | ガーストナー波 12 成分（PM 型スペクトルで有義波高に正規化）。浮力（CPU）と海面の描画（GPU）で同じ成分を使う |
| 艦内の水 | 艦体座標に固定した格子（h = 0.42〜0.6 m）上の MLS-MPM。弱圧縮性（線形の状態方程式、上甲板までの水深 7 m で 12% 縮む剛性）。艦の傾き・並進加速度・回転（遠心力・オイラー力・コリオリ力）を見かけの力として入れる |
| 流入 | 開口部ごとに、海面下の深さと部屋の水位の差からオリフィス式 Q = Cd·A·√(2gΔh) で流量を求め、その分の粒子を噴流の速さで生成する。海面より上の開口からは水がこぼれ出る |
| 連成 | GPU で水の質量・重心・慣性テンソルを集計し、艦体と合成して剛体の質量特性にする（付加重量法。自由表面の揺れによる重心移動も反映） |
| 区画 | 水密隔壁 14 枚・15 水密区画 + 船首楼。水密扉 6 枚・水密ハッチ 2 枚・船外の開口 11 か所（ハッチ・天窓・缶室の給気口・船首楼の扉）は開閉できる。隔壁・甲板は格子の 1 層として厳密に水密（テストで保証） |
| 空気 | 部屋ごとの空気量（等温・ボイルの法則）。扉の上端が水面より上ならその部屋どうしは同じ圧力。閉じ込められた空気は水に押されて縮み、流入を押し返す（エアクッション）。開口の水面より上の部分から空気が出入りし、水中なら外の水圧を超えた分だけ泡で抜ける。GPU 流体には部屋の境目の圧力の段差として入れる |
| 破断 | 外板の点ごとに（空気圧 + 中の水圧）− 外の水圧 を強度（外板 0.4 MPa（高張力鋼）・甲板 0.25 MPa・閉じた開口 0.1 MPa、±15%）と比べ、0.3 s 続けて超えたら破る。閉じた開口は蓋が外れて開き、それ以外は 0.8 m の穴になる。外向き（中の空気が破裂させる）と内向き（沈んだ密閉区画が圧潰する）の両方 |

### 既知の限界

- 格子 0.5 m では、扉のような細い開口を通る艦内の流れが、せきの流量式の見積もりの 1/3〜1/4 と遅い（流量は扉の幅に比例する）。そのため水密扉は実物（幅 0.6〜0.7 m）より広い 1.6 m にしている
- 海面下の開口からは水が入るだけで、出ていかない。艦内の水位や空気圧が外の海より高くなると、その開口は閉じた扱いになる。そのため、噴き込んだ水に縮められた区画の空気がそのまま残ることがある（海面より上の開口からは水がこぼれ出る）
- 艦体の縦強度（船体の折損）と、艦内の隔壁の破れは扱わない

## 構成

| ファイル | 役割 |
| --- | --- |
| `src/hull.js` | 艦体形状の SSOT（物理・格子・描画が共通で参照）。船首楼の段・巡洋艦型船尾 |
| `src/layout.js` | 艦内配置の SSOT（隔壁・甲板・部屋・扉・ハッチ・機器・船外開口・強度） |
| `src/voxel.js` / `src/shipgrid.js` | 流体格子の分類・距離場・滑り境界、破口の部屋ごとの分割 |
| `src/flooding.js` | 部屋の水位と開口部の流量 |
| `src/air.js` | 艦内の空気（圧力・部屋のつながり・空気の出入り・外板の荷重と強度） |
| `src/cameraKeys.js` | W A S D でのカメラ移動量 |
| `src/waves.js` | 波の成分と海面高さ |
| `src/sim.js` / `src/massprops.js` | 艦体の運動と質量特性の合成 |
| `src/gpu/fluid.js` | GPU 流体（WebGPU compute / three.js TSL） |
| `src/render/` | 舞台・艦の 3D モデル（艦橋・煙突・主砲・魚雷発射管は描画のみ）・海面・流体の描画（スクリーンスペース流体）・効果 |
| `src/ui/` / `index.html` / `styles.css` | 区画図・チャート・操作パネル |
| `dev/` | 開発用ページ（流体のセルフテスト、流体なしの艦モデル確認、区画図の確認） |

## テストの範囲

`npm test` は node 上で動く部分を検証する。対象は艦型（寸法・排水量・重心）、区画の水密性、扉の開閉による連結、破口の分割、距離場、水位と流量、空気圧とエアクッションの釣り合い、外板の荷重、波、艦体の浮き方と沈み方（2 区画浸水・機関区画全部の浸水でも浮く）、カメラ移動。
GPU 流体は `dev/fluid-selftest`（ブラウザ）で、静水・水密・扉・空気圧の段差・流入を確かめる。
GPU 流体と描画は node で動かせないため、ブラウザで `window.__app.advance(n)`（描画を待たずに n フレーム進める）を使って確認する。
